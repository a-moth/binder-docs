# CLAUDE.md: working guide for binder-docs

Read this before working in the repo. It records what the repo is, how it is
laid out, what exists, and what is missing.

## Big picture

This repo holds the printable templates for a **physical A4 ring binder**
(cover: "The Hellyers"). The binder is split into **sections**, each with
laminated sub-tabs. Every printed page is designed in **Scribus 1.6.3** and
exported to PDF.

The first commit **initialised the repository** with the user's uploaded files.
Nothing in that commit was generated by Claude.

## Rules

1. **`.sla` is the master.** Change the Scribus source, then re-export the
   PDF. Never treat a PDF as the thing to edit.
   - Exception: `finance/budgets/budget-pages-1.pdf` is a **one-off with no
     source**. It was made in a browser, not Scribus. Keep it as a finished file.
2. **Folders follow the binder:** `<section>/<sub-tab>/…`. Pages that sit in a
   section's main area (before any sub-tab) go in the section root.
3. **Page order inside every section:**
   divider → section goal (`core` section docs) → section context → **yearly
   worksheet** (Finance, Home, Health, Work only) → sub-tabs.
4. **Theme:** the Autumn palette below, as already used in the documents.
5. **Icons:** Lucide only, plus the custom illustrations in `assets/custom/`
   (drawn by `scripts/make-custom.py`). Never hand-colour one: edit the script
   and rerun. New icons are **brown highlight**
   or the colour of their area (section cardstock or disability pride colour).
   - Checklist = Lucide `list-checks` in cream on a rounded **Admin-blue**
     (`#626E7A`) tile (`list-checks-admin`), on every section's pages.
     Work (general work) uses `list-checks-pride`: brand ink on pride-flag stripes.
   - Divider icons use `brown-highlight`, because dividers print on cardstock in
     the section colour.
6. **Images live in `assets/`**, linked by relative path from the `.sla` file.
   After moving a `.sla` or adding icons, run `python3 scripts/relink-images.py`
   (it finds every `.sla`; the top-level folder sets the checklist colour).
7. **Don't fill in missing documents without asking.** Follow "Making new
   documents" below.

## Making new documents

The user hand-edits everything Claude makes until it's right for the binder.

1. **One subsection at a time.** The user names the subsection. Claude proposes
   the list of documents for it, waits for an OK, then makes them. Don't jump
   ahead to other subsections.
2. **Label every file Claude makes in its name:** `-claude` before the
   extension, e.g. `health/letters/letter-log-claude.sla`. This applies to
   exports too (`export-pdf.sh` adds it). The user removes the suffix once a
   file is finished. Never rename or edit a file the user has de-labelled
   without asking.
   - Tooling isn't renamed: `scripts/*` and the generated `assets/` icons are
     Claude-made by definition.
3. **Every document = a `.sla` and its PDF, side by side** in the same folder,
   with the same name (`foo-claude.sla` + `foo-claude.pdf`). Export with
   `scripts/export-pdf.sh`, then render the PDF and check it before committing.
4. **Match the existing style** (see "Page style") unless the user says
   otherwise: Autumn colours, line weights, whitespace and shape types.
5. **More rules will come** as the work goes on. Add each one here when the
   user gives it.
6. Log each new document in the "Made by Claude" list at the end of this file.

## Section notes (from the user)

- **Finance › Tracked** holds the filled-in Yearly and Monthly pages. Monthly is
  filled in digitally each month, then printed and filed here. Yearly holds the
  recurring payments (annual, semiannual, quarterly).
- No debt tracking needed: last month's costs are paid off the next month.
- Subscription status: two unnamed columns at the end of each row, each with
  two stacked, labelled boxes: **Trial** above **Active**, then **Paused**
  above **Cancelled**.
- Groceries and Cash pages are laminated and wiped. No instruction notes on
  the pages themselves; the Cash page has a space to glue a cash pocket. Items left in the
  pantry or freezer move to the Pantry / Freezer stock pages (donut = how much is
  left, count in the middle, meal ideas beside it). 4–6 items per stock page.
- **Finance › Daily** is a laminated *planning* page: Day + Date, a large
  Admin-blue **Budget left** box with 3 currency budgets, cost lines
  (description + one box for currency and cost) and currency transfers. Each
  day is summarised by category onto Weekly; each week onto Monthly. No
  instructions on the page. No mushroom on this page (the budget box sits there).
- **Finance › Digitise** is a log of digitised paperwork: what it is,
  amount (currency + cost), a wide "saved to" column (where the file is),  Scanned ☐, Archived ☐
  (paper moved to the Archive pocket).
- **Home › Yearly** is for tasks, not costs: Annual / Biannual / Quarterly
  home tasks (the user's word is "tasks", not "jobs"), same layout as Finance Yearly.
  Under each task: **When** (month/date to do it) and **Length** (estimated time; the user's word is "Length").
- **Home › Progress** (both pages laminated, no instructions on them):
  - Rooms page: Bedroom, Office, Living room, Kitchen, each with a progress
    donut (10 slots, one per line) and up to 10 current-project lines to tick off.
  - Project page: one project per page, printed in multiples, in no fixed
    order. Donut top left (one slot per task line, 12) with a Started date
    under it (no Done date). Title
    and a large taped-notes area to the right of the donut. Task list where
    each task has **Item #** and **Month** boxes pointing to its cost in
    Finance. A paper holder sits behind each project page (not mentioned on
    the page). No mushroom on this page.
- **Home › Inventory**: Item · Replacement (cost to replace, with £ / $ / €
  checkboxes in the same cell, no separate currency column) · Room.
- Goals are wants: date first wanted (to decide later whether to erase it or
  keep it until it gets a pocket) and estimated cost, compared with savings at a
  glance. Savings pockets are folded and glued/taped to the page, with the goal
  and a Reached box above each.

## Page style (measured from the user's documents)

- **Page:** A4 portrait, 595 × 842 pt. Content sits between x 42–581 pt and
  y 42–800 pt (about 15 mm of white space on every side).
- **Header** (`cleaning page` master): a cream-base bar with a 2.83 pt (1 mm)
  brown-dark outline across the top, 512 × 34 pt. The checklist icon overlaps
  its left end, and the page title sits right-aligned inside it in Latin
  Modern Mono 20, brown dark.
- **Shapes:** plain rectangles only, square corners (no rounding).
  - Main boxes: 2.83 pt (1 mm) brown-dark outline, cream-base fill.
  - Inner boxes: 1.42 pt (0.5 mm) brown-dark outline, usually lens-highlight
    fill, sometimes cream base.
  - Gap between stacked boxes: about 14 pt.
- **Lines:**
  - Write-on lines: 1 pt black, 25 pt apart, inset about 7 pt from the box edge.
  - Rules and dividers: 2.83 pt or 1.42 pt brown dark.
- **Type:**
  - Titles: Latin Modern Mono 20, or 16 for box titles.
  - Labels: Latin Modern Sans Bold 10–14.
  - Body: Latin Modern Sans 12.
  - Occasional emphasis: Latin Modern Mono Italic 14.
  - Comic Relief Bold 12 appears only in `core/core-layouts.sla`
    (Google Fonts; `setup-tools.sh` installs it).
- **Icons:** see Rules 5–6. The checklist sits top-left on every master page.
- **Spacing:** keep at least ~14 pt between a box and the header bar or another
  box, so outlines never read as doubled lines.
- **Contrast:** text needs at least 4.5:1 against its fill (3:1 for icons).
  On Admin blue use **white** text (5.2:1). Cream on Admin is only 3.7:1, which
  is fine for the checklist icon but not for text.

## File types

| Extension  | What it is                                         | Edit?                   |
|------------|----------------------------------------------------|-------------------------|
| `.sla` | Scribus 1.6.3 document (XML). This is the source.  | Yes                     |
| `.pdf`     | Exported print file. Some are fillable forms.      | No, re-export it        |
| `.svg`/`.png` in `assets/` | Generated Lucide icons             | No, rerun the script    |
| `assets/custom/*`          | Custom illustrations               | No, rerun make-custom.py |
| `scripts/*.py`             | Repo tooling (Python 3)            | Yes                     |

Scribus format notes (useful when reading or editing the XML directly):
- Page size is A4 (595.28 × 841.89 pt). Margins are 40 pt. Pages are stacked
  vertically on one canvas, so an object's `YPOS` includes its page's offset.
- Master pages: `Normal` and `cleaning page`. The `cleaning page` master holds
  the header bar and the checklist icon.
- Fonts: Latin Modern Mono 10 (headings), Latin Modern Sans 10 (body),
  DejaVu Sans (default).
- `PTYPE` 2 = image frame, 4 = text frame, 5 = line, 6 = shape. `PFILE` is the
  image path, relative to the `.sla` file. `SCALETYPE="1"` = scale to frame;
  `RATIO="0"` = stretch (proportional off), `RATIO="1"` = keep proportions.
  Headless Scribus uses the saved `LOCALSCX/Y`, so `relink-images.py` writes
  them. Checklists are always stretched to fill their frame. `ITEXT CH="…"` is the visible text.
- The "fillable" variants hold PDF form fields. Keep them in step with their
  plain twins.
- `scripts/split-sla-page.py SRC PAGE OUT` moves one page into its own file.
- **New session? Run `bash scripts/setup-tools.sh` first** (Scribus, xvfb,
  fonts incl. Comic Relief, cairosvg).
- `scripts/export-pdf.sh FILE.sla …` exports `FILE-claude.pdf` next to it,
  headless, with lossless images (needs `scribus` + `xvfb-run`; Scribus 1.6.1 here, the user has 1.6.3). It
  never saves the `.sla`. Never save a `.sla` from this container's Scribus:
  that would downgrade the file version.
